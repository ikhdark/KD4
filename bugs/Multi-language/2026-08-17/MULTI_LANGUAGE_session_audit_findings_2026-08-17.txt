### Root causes

1. **Repeated full workspace fingerprints**

   Both outer `exec` and nested `exec_command` calls are classified as workspace observers in [tool_history.rs](C:/Users/kuh/Desktop/kd4/codex-rs/core/src/tool_history.rs:1247). Each observer captures a workspace identity before and after execution in [parallel.rs](C:/Users/kuh/Desktop/kd4/codex-rs/core/src/tools/parallel.rs:719) and [parallel.rs](C:/Users/kuh/Desktop/kd4/codex-rs/core/src/tools/parallel.rs:138).

   Every capture launches six Git queries and hashes every untracked file’s entire contents in [git_workspace.rs](C:/Users/kuh/Desktop/kd4/codex-rs/core/src/git_workspace.rs:179) and [git_workspace.rs](C:/Users/kuh/Desktop/kd4/codex-rs/core/src/git_workspace.rs:246).

   The checkout currently has 1,167 untracked files totaling 35.6 MB, all under `.codex/evals`. Therefore a single code-mode packet can perform the same complete fingerprint repeatedly around the outer program and its nested reads. The command’s displayed “Wall time” excludes this work.

2. **Initial discovery is rejected**

   Both agents’ first `rg` packet was rejected by the broad-search gate at [command_execution.rs](C:/Users/kuh/Desktop/kd4/codex-rs/core/src/tools/command_execution.rs:500). Because the calls were inside `Promise.all`, one rejection failed the whole JavaScript program, preventing successful `git status` or inventory results from reaching the model. See [auto-review failure](C:/Users/kuh/Desktop/LOCAL-KD/sessions/2026/08/17/rollout-2026-08-17T21-16-16-01a012a7-b333-74f2-96d4-c8ff8060b2fd.jsonl:22) and [SOL-audit failure](C:/Users/kuh/Desktop/LOCAL-KD/sessions/2026/08/17/rollout-2026-08-17T21-17-11-01a012a8-861e-7a13-8f5c-425e26c88665.jsonl:23).

   The agents then restart orientation, reread large policy/source-map files, and repeat `git status` rather than progressing.

3. **Read-only commands are marked as possible mutations**

   The mutation classifier fails closed for commands it does not recognize in [turn_diff_tracker.rs](C:/Users/kuh/Desktop/kd4/codex-rs/core/src/turn_diff_tracker.rs:1458). Consequently, `cmd /c type ...` and PowerShell `Get-Content` are treated as unknown mutations.

   The first rollout accumulated `unknown-command-mutation` risks from pure file reads. That path invalidates workspace evidence and records a risk in [task_evidence.rs](C:/Users/kuh/Desktop/kd4/codex-rs/core/src/task_evidence.rs:5167), causing still more orchestration and context churn.

4. **Synthetic task-state messages create noise**

   Any command receipt makes the task “tracked” in [task_evidence.rs](C:/Users/kuh/Desktop/kd4/codex-rs/core/src/task_evidence.rs:3013), even without a durable plan. The runtime then injects `<kd4_task_state_v1>` as a new user message after commands, including a fabricated “Complete the active durable task plan” goal. The first rollout received three such injections and four separate sampling boundaries.

5. **Large uncached prompt is a secondary cost**

   The SOL audit’s first request contained 12,519 tool-schema tokens out of a 21,945-token logical prompt—57%—with zero cached tokens and high reasoning effort. This explains several seconds of model latency, but only 17% of the total wall time. Official guidance recommends lean tool sets and `low` effort for latency-sensitive work; high effort should be used only when measurements justify it. [OpenAI model guidance](https://developers.openai.com/api/docs/guides/latest-model)

### Recommended fix order

1. Make only one layer own workspace evidence: outer `exec` or nested calls, never both. Capture once per program or workspace revision rather than twice per read.
2. Exclude generated `.codex/evals` artifacts from source fingerprints, or make them ignored runtime state.
3. Remove or relax the hard broad-`rg` gate. At minimum, return a per-call failure without rejecting the entire code-mode packet.
4. Recognize direct file reads as read-only, or provide a native file-reading tool that bypasses mutation tracking.
5. Suppress task-evidence world-state injection when no actual plan, edit, or mutation exists.
6. Reduce the default tool manifest and use lower reasoning effort for routine inspection.

There is no evidence here of a provider stall, model fallback, approval deadlock, or permanent agent deadlock. The second task was manually interrupted while orchestration was still processing; the first log simply ends at an unresolved tool call. No files were changed during this audit.
