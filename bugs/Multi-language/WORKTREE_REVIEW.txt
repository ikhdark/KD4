VALIDATED FINDINGS AND INTENDED DISPOSITIONS
============================================

F-01 | CONFIRMED HIGH | Automatic push renewal resets Spanish locale
Evidence: scripts/templates/service-worker.js readStoredPushTopics() returns only
topics, saveReplacementPushSubscription() omits locale, and
webPushSubscriptions.normalizeSubscription() defaults an omitted locale to en.
Impact: endpoint rotation can change localized notification click routing without
resident action.
Disposition: rename/expand stored state lookup to return topics plus locale,
require the stored locale, carry it through renewal, include it in the replacement
POST, update API/storage state representations and regression tests, and regenerate
public/sw.js.

F-02 | CONFIRMED HIGH | Push renewal uses split save/delete writes
Evidence: the service worker POSTs the replacement and then separately DELETEs the
old endpoint, while the existing API and repository already accept
previousEndpoint for one atomic replacement operation.
Impact: worker termination or DELETE failure can leave duplicate/stale endpoints.
Disposition: include previousEndpoint in the replacement POST, remove the DELETE,
and update tests/generated worker to prove one mutation performs the migration.

F-03 | CONFIRMED HIGH | Zero-target broadcasts finalize as sent
Evidence: alertBroadcastRepository.finalizeBroadcastDelivery maps total = 0 to
sent; sendAlertBroadcastEmails independently returns sent for an empty recipient
list; the composer permits a zero audience after preview.
Impact: an operator can reasonably read sent as successful direct delivery when no
resident was targeted.
Disposition: add the explicit durable no_targets outcome through a new migration,
repository/model unions and finalization/recovery SQL, email delivery results,
admin presentation, paired English/Spanish copy, tests, migration manifest, and
SOURCEMAP. Publication remains separate and can still complete.

F-04 | CONFIRMED MEDIUM | Restore Blob and pg_restore operations are unbounded
Evidence: database-restore.mjs gives private Blob get/pipeline, pg_restore
--version, pg_restore --list, and spawned pg_restore no deadline.
Impact: an emergency restore can hang indefinitely, including after an in-place
write fence is activated.
Disposition: add conservative Blob download, preflight, and restore deadlines;
terminate then force-kill a timed-out child; settle process listeners once; emit a
clear bounded failure while preserving the existing rule that an ambiguous failed
in-place restore leaves its write fence active for explicit operator review.

F-05 | CONFIRMED MEDIUM | Retention deletion omits the configured Blob deadline
Evidence: database-backup.mjs applies blobRequestTimeoutMs to publication and
failed-publication cleanup but not scheduled-retention del().
Impact: pruning can hang after a valid backup is verified, and ambiguous deletion
can desynchronize object and manifest state.
Disposition: add the deadline, reconcile artifact and sidecar existence after an
ambiguous delete, mark only confirmed-absent manifests deleted, record a distinct
privacy-safe prune-failure audit outcome, and report verified backup creation
separately from non-fatal old-backup pruning failure.

F-06 | CONFIRMED MEDIUM | Push receipt CacheStorage is unbounded
Evidence: each broadcast writes a permanent martindale-push-receipts-v1 cache
entry; activate cleanup handles only martindale-static-* release caches.
Impact: long-lived installations accumulate uncontrolled state and eventually
depend on browser quota eviction.
Disposition: version the receipt cache, store receipt timestamps, prune by a replay
window longer than normal delivery retry/expiry, enforce a maximum entry count,
prune on activation and insertion, clean obsolete receipt cache versions, and add
expiry/count tests.

F-07 | CONFIRMED MEDIUM | SOURCEMAP migration topology stops at 0006
Evidence: the canonical narrative lists 0001-0006 while the manifest and current
owners include 0007, 0008, and 0009.
Impact: maintainers can miss current idempotency, localization, permission, and
metrics schema owners.
Disposition: update the narrative and table ownership through the new latest
migration created by F-03, advance map revision/date, and add a mechanical check
that the map's declared latest migration matches migrations/manifest.json.

F-08 | CONFIRMED LOW | SOURCEMAP indexed-route summary omits one real route
Evidence: the short summary omits /codes-permits-planning while routes.ts and the
same document's detailed route table include it.
Impact: route/SEO impact sweeps can be incomplete.
Disposition: add the route to the summary and extend the mechanical source-map
check so its indexed route inventory must exactly match src/i18n/routes.ts.

F-09 | CONFIRMED MEDIUM | Critical data workflows use mutable action tags
Evidence: data-release-gate.yml and data-operations-tests.yml use mutable v6/v5
action tags, while ci.yml and data-backup.yml use reviewed immutable SHAs and
checkout persist-credentials:false.
Impact: the same candidate can execute different third-party action code on rerun.
Disposition: use the repository's reviewed checkout/setup-node/pnpm immutable pins,
disable persisted checkout credentials, and add a workflow policy check rejecting
external uses that are not pinned to a full commit SHA.

F-10 | CONFIRMED MEDIUM | Data failure proof does not run on main pushes
Evidence: data-operations-tests.yml has pull_request and workflow_dispatch only;
the runbook requires its PostgreSQL proof for the exact production candidate.
Impact: merge-created main SHAs can lack required evidence unless manually run.
Disposition: add push main, retain manual dispatch, add concurrency/timeout bounds,
and document the exact-candidate automatic proof.

F-11 | CONFIRMED MEDIUM CONTROL GAP | Applied release enforcement lacks a gate
Evidence: release-assurance-gaps.txt explicitly states the repository cannot prove
the documented GitHub ruleset and production-promotion controls are applied.
Impact: green workflows can exist without actually blocking an unsafe promotion.
Disposition: make a short-lived, candidate-bound, HMAC-signed enforcement
attestation mandatory in the production data release gate. Validate repository,
branch, candidate SHA, exact required check names, ruleset URL, Vercel project and
promotion-gate identifiers, verification/expiry times, and signature. Update the
runbook and add unit coverage. This implements the runbook's accepted external
immutable-control path when CI cannot reliably read administrative GitHub/Vercel
configuration with its default token.

F-12 | CONFIRMED MEDIUM VALIDATION GAP | No live named-admin HTTP/database proof
Evidence: admin identity tests mock PostgreSQL and no release workflow provisions a
fake named admin and exercises cookies, MFA, permissions, and revocation over HTTP.
Impact: cross-layer deployment/runtime failures can pass unit verification.
Disposition: add a disposable-PostgreSQL workflow job that migrates a synthetic
database, bootstraps a fake metrics-only MFA administrator without logging secrets,
starts the production app in CI, proves correct MFA login and cookie issuance,
proves an allowed request, proves permission denial, revokes the session, proves
post-revocation denial, and uploads privacy-safe candidate-bound evidence.

F-13 | CONFIRMED MEDIUM VALIDATION GAP | No encrypted backup-to-restore rehearsal
Evidence: repository docs acknowledge no lane creates an encrypted backup and runs
database:restore --apply against an isolated disposable target.
Impact: backup creation can remain green while the integrated encrypted archive,
decrypt, pg_restore, schema, and verification path is broken.
Disposition: add a guarded localhost-only local rehearsal mode to the production
backup owner, then add a disposable-PostgreSQL workflow job that creates synthetic
source data, produces/verifies an encrypted restore-point backup, restores it with
the production restore script into a distinct empty database, verifies migration
state and safe synthetic counts, uploads candidate/fingerprint evidence, and drops
the disposable databases with the runner.
