F-02 — MEDIUM — The public decompression-ratio limit rejects a valid replay

Invariant violated:
Upload safety limits must bound resource use without rejecting valid replay
containers that remain below the independent absolute compressed and
decompressed byte ceilings.

Cause and reachable path:
- `src/replay/core/api/replayUploadLimits.ts:11` derives the public ratio as
  40 MiB / 4 MiB = 10, and lines 39-57 install that limit for the public
  runtime.
- `src/replay/lib/parsers/ReplayParser.ts:437` rejects any replay whose declared
  inflated size exceeds compressed bytes times that ratio.
- `src/replay/tests/fixture-harness/replayExternalFixtureHarness.test.ts:64`
  exercises the checked-in wc3.tools replay corpus.

Practical consequence:
`src/replay/tests/fixtures/wc3-tools/1.w3g` is only 594 bytes and inflates to
8,192 bytes (ratio 13.79). The default public parser rejects it as
`REPLAY_TOO_LARGE`, even though the inflated result is tiny.

Fresh reproduction:
- Default limits: failure, `8192 exceeds maxDecompressionRatio 10 for
  compressed size 594`.
- Identical bytes with ratio 20: successful parse, 2 players, confidence 100.

required confidence 100 to 98 because its upgraded main building is counted as

Evidence:
