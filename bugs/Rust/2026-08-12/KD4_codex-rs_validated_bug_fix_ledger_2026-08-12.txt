Retained audit-confirmed findings

[CONFIRMED] MCP-07 (critical): an MCP openai/file argument can upload an
arbitrary host path. core/src/mcp_openai_file.rs joins untrusted text to cwd;
absolute paths replace cwd, parent traversal is accepted, and the selected
environment file API is invoked with sandbox=None. Repair: reject absolute and
parent/prefix/root components and perform one bounded, identity-checked, confined
read rooted at the selected environment cwd. Proof: absolute, parent,
and symlink/reparse escapes fail while an in-root file uploads.

[CONFIRMED] MCP-08 (high): MCP upload checks metadata and later reopens the
path for streaming, so identity and size can change between the two operations.
Repair jointly with MCP-07 by uploading the bytes from the same bounded,
confined snapshot. Proof: oversized/changed inputs cannot cross the limit.

[CONFIRMED] MCP-09 (medium): array-valued file arguments upload sequentially;
failure after an earlier upload leaves remote files behind. Repair: stage every
local snapshot before network mutation and delete already-created remote files
if a later upload fails before tool dispatch. Proof: later failure triggers
cleanup of every earlier upload.

[CONFIRMED] VAL-01 (medium): LocalAgentTaskStore::record_validation_call looks
for exact reusable evidence only among the latest 64 successful rows. Repair:
query the exact normalized evidence key without a fixed recency window. Proof:
the matching row is reused with more than 64 newer nonmatches.

[CONFIRMED] VAL-02 (high): a prohibited instruction such as "do not run tests"
fails open when the requested command is an opaque make/just/task/npm wrapper,
because denial is gated by successful validation classification. Repair: run a
separate fail-closed prohibition detector before classification. Proof: opaque
wrappers are denied while non-validation commands are not overblocked.

[CONFIRMED] VAL-04 (medium): ValidationLeaderOwnership::complete removes the
in-flight entry before publishing the result and notifying waiters, allowing a
second leader in the gap. Repair: publish terminal state and notify before a
conditional registry removal. Proof: a concurrent joiner cannot become leader.

[CONFIRMED] VAL-05 (medium): one observation writes three validation-history
scope keys through three independent transactions and prunes three times.
Repair: add one batch transaction that records all scopes and prunes once.
Proof: all scopes commit together and one injected failure leaves none visible.

[CONFIRMED] VAL-06 (medium): concurrent validation-history key creation can let
the create_new loser read the winner's partially written 32-byte key. Repair:
write/sync a private temporary file and install atomically without replacement,
or retry boundedly until a complete key is visible. Proof: concurrent creation
always yields the same complete key.

[CONFIRMED] VAL-07 (low): one process-global WRITE_WARNING_EMITTED bit suppresses
all later validation-history write failure classes. Repair: rate-limit by stable
failure class and emit recovery. Proof: distinct failures are observable and a
recovered class may report a later regression.

[CONFIRMED] VAL-08 (medium): prediction_from_aggregate advertises 0.95 confidence
with n>=8 using a fixed normal z value over estimated variance and censored
samples. Repair: use a small-sample t bound and exclude/explicitly model censored
samples before allowing a skip. Proof: marginal small/censored samples no longer
produce a 0.95 skip.

[CONFIRMED] TASK-01 (high): task coordinator restart initialization loads only
the first 256 bindings and never paginates. Repair: enumerate all pages with a
stable cursor or use exact store lookup for missing bindings. Proof: binding 257
and later are restored.

[CONFIRMED] TASK-02 (high): finish_focused_validation_with_output constructs a
fresh default ValidationEvidence, discarding immutable evidence carried by its
token, so the task store rejects completion. Repair: preserve token evidence
and update only retained output fields. Proof: immutable evidence survives and
completion succeeds.

[CONFIRMED] TASK-03 (medium): source locate_task runs in spawn_blocking without
a cancellation token; cancelled scans keep consuming CPU and can publish cache
state. Repair: thread cooperative cancellation through task_locator and do not
publish partial cancelled results. Proof: cancellation stops a large scan and
leaves no reusable partial entry.

[CONFIRMED] TASK-04 (low): task_locator's process-global per-repository mutex map
holds a strong Arc for every observed path and never evicts. Repair: store Weak
entries and sweep dead keys. Proof: transient repositories do not grow the map.

[CONFIRMED] TASK-05 (high): residency eviction holds its claim while awaiting
rollout materialization and shutdown without a deadline. Repair: bound both
stages, cancel/force cleanup on expiry, and always release reservation state.
Proof: a stuck rollout cannot block future capacity forever.

[CONFIRMED] TASK-06 (high): PendingSpawnCleanup::drop depends on a Tokio runtime
and otherwise only warns; even with a runtime it launches detached rollback.
Repair: make rollback explicit and awaited on every error path, with a durable
or runtime-independent fallback for unwind/drop. Proof: no-runtime and shutdown
paths remove the child and binding.

[CONFIRMED] TASK-07 (medium): drop_last_n_user_turns calls replace with unchanged
history when there are no user turns, bumping version and invalidating caches.
Repair: return without replace. Proof: no-user-turn history/version is unchanged.

[CONFIRMED] TASK-08 (medium): MCP skill dependency cancellation is checked only
during permission prompting, not OAuth, config persistence, or client refresh.
Repair: propagate the token through each stage and reconcile completed effects
when cancellation arrives. Proof: cancellation at every boundary terminates and

[CONFIRMED] TASK-09 (medium): OAuth credentials can be acquired before config is
persisted; a later failure leaves credentials without the corresponding config.
Repair: journal acquired credentials and revoke/rollback them on pre-commit
failure, or stage config transactionally. Proof: injected config/refresh errors
leave neither an orphan credential nor a half-applied config.

[CONFIRMED] EXEC-01 (low): CommandExecutionLedger's workspace mutation-gate map

[CONFIRMED] MCP-05 (high): cancelling an in-flight MCP tool call drops the local

Proof: outcome wording and telemetry never claim confirmed cancellation on a

[CONFIRMED] TUI-01 (high): untracked-file diff fallback reads whole files with

[CONFIRMED] TUI-03 (high): untracked diff performs metadata followed by a fresh

[CONFIRMED] TUI-04 (medium): NUL-delimited git path output is converted to UTF-8

[CONFIRMED] TIME-03 (high): multi-recipient current-time dispatch removes the
entire callback after any later send failure, even if an earlier recipient
received the request and can respond. Repair: retain successful recipients and

Proof: first success plus second failure still accepts the first response.

[CONFIRMED] VAL-03 (high): shell validation joins singleflight with a turn-local

[CONFIRMED] EXEC-02 (high): the production multi-agent cleanup path calls the

[CONFIRMED] EXEC-03 (high): WorkspaceMutationGuard::drop depends on a current

[CONFIRMED] EXEC-04 (medium): the 128-entry command-attempt cache can evict

[CONFIRMED] EXEC-05 (high): async output-drain notification occurs only on the

[CONFIRMED] EXEC-06 (high): pending-process cleanup uses `?` inside the process
