The current wait path returns once the caller’s yield interval expires ([wait_handler.rs](/C:/Users/kuh/Desktop/kd4/codex-rs/core/src/tools/code_mode/wait_handler.rs:105)), requiring another model generation even when the only valid action remains “wait.”

Keep the original tool call suspended until meaningful output, completion, failure, cancellation, or a real operation deadline. UI progress can remain host-generated.

Safety: retain cancellation, user interruption, operation timeouts, and a fallback to today’s behavior. Do not simply restore an arbitrary five-minute hold.

3. Generalize the in-flight owner-drained continuation work

The repository already models deterministic continuations for waits, source bundles, coverage, artifact ranges, and agent events ([protocol.rs](/C:/Users/kuh/Desktop/kd4/codex-rs/protocol/src/protocol.rs:2294)). Current uncommitted work safely drains artifact subdivision and preserves the recovered content ([read_tool_output.rs](/C:/Users/kuh/Desktop/kd4/codex-rs/core/src/tools/handlers/read_tool_output.rs:143)).

Generalize that mechanism to owner-declared continuations such as:

- Oversized artifact subdivision
- Cursor pagination
- Explicit remaining source ranges
- Unchanged process or agent waits
- Predeclared validation evidence collection

The host should continue only when the tool supplies an immutable identity, state revision, exact next action, and bounded result. Any ambiguity returns to the model.

Safety: fail open to the existing model loop. This avoids generations without moving judgment into heuristics.

4. Default proven deterministic continuations to low reasoning

The reasoning governor already supports a special effort for deterministic continuations, but it activates only when `reasoning_phase_efforts.deterministic_continuation` is configured ([reasoning_governor.rs](/C:/Users/kuh/Desktop/kd4/codex-rs/core/src/session/reasoning_governor.rs:2627), [config_toml.rs](/C:/Users/kuh/Desktop/kd4/codex-rs/config/src/config_toml.rs:68)). The active fork configuration uses high reasoning and does not set this override.

The immediate configuration-level win is:

```toml
[reasoning_phase_efforts]
deterministic_continuation = "low"
```

A code-level improvement would make low the safe fallback whenever an owner receipt proves the continuation deterministic. Diagnose, implement, verify, and finalization generations retain their configured effort.

Safety: scope it strictly to receipt-backed continuations; do not globally lower reasoning.

5. Shrink and content-address the stable prompt/tool prefix

In current live sessions, the three model-visible tool definitions serialize to about 38K characters:

- `exec`: about 26K
- Agent namespace: about 10K

The code-mode prompt currently incorporates full deferred tool definitions ([spec_plan.rs](/C:/Users/kuh/Desktop/kd4/codex-rs/core/src/tools/spec_plan.rs:505)). The agent namespace also remains visible when delegation is explicit-request-only. Meanwhile, the prompt cache key defaults to the thread UUID, preventing identical stable prefixes from naturally sharing a key across threads and subagents ([client.rs](/C:/Users/kuh/Desktop/kd4/codex-rs/core/src/client.rs:1357)).

Use a compact searchable deferred-tool catalog, defer the agent schema until requested, and derive the cache key from the stable prefix fingerprint—including model, instructions, permissions, and active schema versions—rather than thread identity.

Safety: exact schemas remain available through tool search; mismatched hashes cannot reuse a prefix.
