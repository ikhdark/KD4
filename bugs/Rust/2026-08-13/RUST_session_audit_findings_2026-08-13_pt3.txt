# Fix terminalization gaps 1–3

## Summary

- Make terminal delivery at least once without changing a semantic outcome after it becomes durably authoritative.
- Deduplicate app-server state reduction separately from client-notification delivery, allowing identical replays to repair failed notification handoff.
- Recover exact authoritative events unchanged; recover final-proof memos only after exact turn association, identity validation, and renewed quiescence.

## Implementation changes

### 1. Immutable authority and runtime convergence

- Add a versioned authoritative terminal record containing thread/turn identity, exact serialized `EventMsg`, canonical fingerprint, semantic outcome, and associated final-proof identity.
- Establish authority by durably writing the event to task evidence or the rollout. Reconcile both stores after ambiguous write errors before concluding no authority exists.
- Once authority exists:
  - Always reuse its exact event and outcome.
  - Make `AlreadyClaimed` return that record for replay instead of suppressing delivery.
  - Reject any same-turn candidate with a different fingerprint.
  - Record claim, persistence, dispatch, acknowledgement, notification, or cleanup failures as infrastructure diagnostics only; never emit a conflicting or status-changing terminal result.
- Emit a degraded failed terminal event only when neither durable store contains an authoritative decision/event.
- Track live delivery, app-server acknowledgement, runtime/status convergence, rollout mirroring, parent notification, and cleanup independently in terminal receipts.
- Route normal completion, `AlreadyClaimed`, fail-safe, and restart recovery through one convergence path that:
  - Applies `agent_status` from the authoritative event.
  - Replays the exact event while app-server acknowledgement is absent or delivery is uncertain.
  - Releases the matching active turn only after status and live terminal handoff have converged.
  - Retries post-terminal effects independently.
- Give child-to-parent completion envelopes a deterministic existing communication ID derived from terminal identity, fingerprint, and effect kind. Deduplicate that ID in the parent input path.
- Map a genuinely failed `TurnComplete` carrying an embedded error to `Errored`; a successful authoritative completion remains `Completed` despite later infrastructure failures.

### 2. App-server state and notification deduplication

- Add a per-thread terminal ledger keyed by turn ID. Each entry stores:
  - Accepted terminal fingerprint.
  - Whether terminal state has been reduced.
  - The exact generated terminal client notification.
  - Notification targets and their outbound-acceptance status.
  - Whether acknowledgement was sent to core.
- Classify terminal events before `ThreadHistoryBuilder`, `ThreadState`, bespoke reduction, or client notification:
  - New terminal for the matching active turn: reduce state exactly once, cache the generated notification, then attempt outbound delivery.
  - Same fingerprint with state reduced and notification accepted: suppress reduction and notification, then ACK.
  - Same fingerprint with state reduced but notification unaccepted or incomplete: do not reduce again; retry only the cached terminal notification.
