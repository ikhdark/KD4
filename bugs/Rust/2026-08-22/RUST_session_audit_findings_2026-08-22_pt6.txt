1. KDA caches `A0` and releases the resource mutex.

3. KDA first reads and caches `B1`.

Violated invariant
→ Generated-output diagnostics and provenance can be attributed to `S0` while depending on an impossible mixture such as `A0/B1`. This can produce false stale/missing-member findings, suppress real findings, or generate a receipt whose inputs do not describe one workspace state.

The resource mutex only protects cache-map mutation and same-key identity. It cannot synchronize an external filesystem writer. This is precisely a logical race even though Rust prevents a memory data race.

Reachable borrow/operation sequence
→ A library caller shares `Arc<Config>`:

1. Analysis A matches selector `X` and increments `X`.
2. Analysis B begins a new epoch and resets `X` to zero while A is still active.
3. A either loses its match, or increments after B’s reset so its match is attributed to B.
4. Reporting iterates the counters while resets or matches continue, allowing different selectors in one report to belong to different epochs.

→ A selector that did match can be reported unmatched, or one coverage vector can combine multiple analysis runs.

Stronger atomic ordering would not repair it: `Relaxed` is sufficient for independent counters, but no ordering can create the missing run-wide epoch. Rust documents `Relaxed` as atomicity without cross-operation ordering in [`Ordering`](https://doc.rust-lang.org/std/sync/atomic/enum.Ordering.html).
