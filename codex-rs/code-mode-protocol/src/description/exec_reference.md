# Exec cell reference

## Results and failures

- Empty terminal drains may include `retained_output` and `retained_output_complete:true`: the complete process-owned combined UTF-8 transcript (at most 4096 bytes and within the output budget). It is not another stream delta, command-success proof or durable-artifact receipt; do not concatenate it with stdout/stderr. Larger, incomplete, binary and explicitly quiet results keep their existing recovery behavior.
- exec_command waits; one still running after the default wait returns a live `session_id` (see await_command). r.output is display text; r.exit_code is status; the host reports failed commands itself. Native stdout/stderr contain only this receipt's independent byte ranges (stream_chunks_complete); streams_complete additionally means the whole command. For polled-command parsing use await_command's top-level stdout/stderr when its streams_complete is true, not terminal's final slices. Before parsing, concatenating, or indexing a result, verify success and representation, and finish its live handle or continuations. A display string is not exact completed data.
- Native failures expose `tool_failure` (also on caught exceptions): inspect `code`, `execution_state`, `effects`, `retry_safe`, `field_errors`, `safe_next_actions` and `live_operations` together. Execution is `not_started` only for owner-confirmed pre-execution rejection, `completed` for an actual invocation receipt (not child-process exit or successful effects), otherwise `unknown`, including missing/lost responses and legacy states. Unknown never proves failure or retry safety. `field_errors` uses exact RFC 6901 argument paths (empty means root), public expected constraints and corrections, never rejected values; omitted diagnostics are marked in details. Codes distinguish invalid syntax, stale input, missing/ambiguous anchors, permission denial, retryable failure, timeout, cancellation and uncertain effects; none grants permission to retry. Resume an existing operation using its owner-issued handle rather than launching a duplicate; cancellation is not rollback. Legacy/unclassified diagnostics remain non-retry-safe.
- Nested deadlines: { timeout_ms } overrides the host default. Expiry reports `tool_failure.code="timed_out"`, not cancellation or process exit; the process may still run. Inspect late evidence on `error.results.completed.value` and any live handle before considering a retry.
- `operation_history` (on results or `tool_failure.details`) retains attempt provenance and surfaces earlier outcomes for the same exact input. Its typed-context fingerprint is not proof of a shared cause; external state may be unknown. Memory is advisory, not a retry ban or permission: changed conditions or transient failures can justify retry after checking effects/live handles. Retry-owner budget receipts distinguish reserved retries, entered attempts, transport scope and agent attempts; unlimited and unknown values are explicit.

## Deterministic recipes

Compose only when the requested transform and next action are already known. Do not guess a repair, infer permission, parse a display as exact data, or declare arbitrary tool success to be task completion. The existing delivery, plan, schema, pending-input and recovery gates still apply. Do not read this reference just to rediscover an eager contract.

- A declared extraction can read a native structured result, check its completeness, call `extract_result` with known pointers, and deliver its text in the same cell. Preserve the returned provenance; extraction is not source-completeness proof.
- A declared edit can construct a hash-bound patch from that cell's source receipt rather than regenerating old lines. For example, only for a request to set `settings.json`'s existing boolean `/enabled` to true:

```js
// @exec: {"deliver": true}
const source = await tools.read_file({path:"settings.json", selectors:[{kind:"json_pointer",pointer:"/enabled"}]});
const row = source.results?.[0];
if (source.complete !== true || source.results?.length !== 1 || row?.status !== "ok" ||
    row.complete !== true || typeof row.value !== "boolean" || typeof source.source_sha256 !== "string")
  throw new Error("complete current boolean selection required");
const operations = [{op:"replace",path:"/enabled",value:true}];
const patch = "*** Begin Patch\n*** Update File: settings.json\n@@ codex-json sha256:" +
  source.source_sha256 + "\n+" + JSON.stringify(operations) + "\n*** End Patch";
const changed = await tools.apply_patch(patch);
if (changed.success !== true || changed.changes_exact !== true)
  throw new Error("edit rejected or effects uncertain; retain its receipt before repair");
text("Set settings.json /enabled to true.");
```

- If requested verification/readback is mechanical, await it after the successful operation and before delivery; do not stop merely to have the model announce the next known call. A failed prerequisite stops dependent work, not independent receipt recovery.
- For whole required files use `read_files(paths,{full:true})`, check every row's status and `file_complete`, and consume only that original snapshot. For known ranges batch selectors. For retained output invoke the producer's `recovery.arguments` with `read_tool_output` in the same cell, narrowing to the required records; follow only required, resumable `remaining_selectors`. Do not reacquire the source or relaunch a producer to recover its output.
- Start authorized independent reads/root work before awaiting a long-lived dependency. Use `Promise.allSettled` for independent fallible operations and `run_graph` for declared dependency/postcondition edges; keep shared writers and builds exclusive. Once dependent work is all that remains, use its existing command/worker wait owner rather than model-mediated polling.

## Stored values

- JS bindings reset per exec; store(key,value)/load(key) retain JSON-serializable data, native results included (exact integers survive; functions and other non-JSON values do not). Store a compact projection when the quota matters. Native integers are JS numbers unless they exceed 2^53, where they become BigInt and JSON.stringify throws; prefer text(result) to print a whole result. Load large JSON once per computation and compare stable keys, not object references across loads. Keep one working body, retiring obsolete copies before storing replacements. Summarize already-consumed machine data without reprinting it. deleteStored(key) drops duplicates. Failed quota cells discard staged stores; check listKeys before resuming. listKeys({after?,limit?}): 1-64, default 32; continue next_after. First-line // @exec: {"persist":true} preserves completed values across host restart.

## Helpers

- `await recover_output(initial, {max_calls?, max_bytes?})`: explicitly continue one original native `read_tool_output` snapshot receipt for nonempty byte selections. Pass the complete receipt, not a printed projection, command log, `read_file` envelope or reconstructed recipe. Returns `{initial,pages,selection_complete}`; pages contain exact native results, not concatenated text. Completion concerns only those original selections, not the whole artifact or task. A complete initial receipt dispatches nothing. On failure, `.evidence` retains the initial packet, every received page and any native cause; a helper limit additionally retains the last verified `recovery` recipe. No retry, producer replay, file reopening, checkpoint publication or permission grant occurs.
  - Call this after the initial read/store cell has successfully completed when that acquisition must survive interruption. This helper uses the existing cell transaction: cancellation does not commit new named-state writes or erase the earlier checkpoint. Catch ordinary errors to retain/inspect `.evidence`; resume interrupted work through the original owner, never infer rollback or successful completion.
  - Only authenticated complete retained snapshots with fixed artifact/hash/size/source-thread identity are eligible. It follows exact advancing `budget`/`page_limit` byte remainders through normal native dispatch. Cancelled/still-writing stops, drift, unavailable bytes, terminal/invalid selectors, overlap and non-progress stop with evidence. `resumable:true` alone is not sufficient. Other selector families remain available through the native tool, not this helper.
  - `max_calls` is 1–64 (default 64); `max_bytes` is 1–8388608 (default 8388608), the aggregate serialized packet budget including `initial`. One maximum 1 MiB native packet is reserved before each dispatch; a tighter remaining budget can stop before a smaller page that might fit. Native source/page/serialized limits remain unchanged. The failing native packet is retained even if it exceeds the helper bound; no further call is launched. Limits are not display budgets.

Prefer these over equivalent read/search/poll plumbing; preserve scope, budgets and failure evidence.
`search_files` uses the registered read-only `file_search` backend (also `inspect_files(search)`) in local full-disk-read environments. It constructs fixed ripgrep arguments, not a shell command, and owns bounded capture/cancellation; worker shell permissions do not change. Older or unsupported hosts retain the command-backed helper and its existing execution-permission requirement. Native `read_file` search selectors remain available for known files without command execution.
- `extract_result(result, {fields:[{name,pointer}], format:"json"|"text"|"csv"|"tsv", row?:{pointer,where:[{pointer,value}]}})` returns `{text,values,provenance}` from an unmodified native structured tool result (also after store/load when trusted metadata fits the existing quota). Declare 1–64 uniquely named fields with exact RFC 6901 pointers; optional row selects exactly one array member by typed equality predicates (1–64). Missing fields/rows, multiple matching rows, invalid declarations, clones and edited results throw; no text parsing or guessed fields. JSON preserves null and exact integers; text requires one non-null scalar; CSV/TSV require non-null scalars, preserve field order and quote delimiters/quotes/newlines. Declarations and the complete return are capped at 1 MiB. Provenance retains native tool/call identity, available source metadata, the declaration and resolved pointers, not proof of source completeness. Use `text(extract_result(r, declaration).text)` with `deliver:true` to deliver the declared answer without another model round; existing success, output-schema and delivery gates still apply.
- `await read_files(paths, {full?, concurrency?, revision?, source_hashes?, environment_id?})`: 1–32 paths; Promise.allSettled rows: {path,status:"fulfilled",value} or {path,status:"rejected",reason}, never outer "ok". value={initial,pages,file_complete,consistency}; text is in initial.results/pages[].results. revision is a full immutable commit OID; native reads verify commit and batch repository/environment identity. Otherwise source_hashes declares every exact path's source_sha256, whole or its first 12 characters; mismatches reject per file with evidence. Undeclared consistency is unknown, readable as value.consistency but left out of a printed row. full defaults false; true recovers only the original retained snapshot. Matching per-file identities, opens and hashes are not an atomic live-workspace snapshot. Check status, consistency and file_complete; byte coverage is not semantic review.
- `await search_files(pattern, {page_size?, cursor?, count_only?, overlapping?, path?, glob?, lines?, max_per_file?, ignore_case?, fixed?, hidden?, no_ignore?, hydrate?, enclosing?, context_lines?, max_hydrated_files?})`: ripgrep returning {files:[{path,count,lines?,source?,hydration?}],match_count,complete,errors?,hint?}. lines adds {line,text}, default max_per_file=10.
  - Matching: A string defaults to ripgrep regex semantics; fixed:true passes the supplied single-line text unchanged via argv, without regex interpretation or shell interpolation. Invalid regex is an error, never a literal fallback. Patterns reject NUL/lone surrogates and fixed strings reject LF rather than silently splitting into alternatives. An array of 1–64 strings or {id,pattern} entries shares one tree scan; arrays default to fixed:true and reject fixed:false. Strings get zero-based string ids; explicit ids must be unique. Multi-pattern literals are 1–1024 UTF-8 bytes each, without newlines/lone surrogates. Default case-sensitive; ignore_case folds ASCII only for arrays/overlapping literals, otherwise ripgrep Unicode rules apply. Every result reports semantics.fixed, case_sensitive and case_folding (none, ascii or ripgrep_unicode), including misses, errors and cursor refusals. fixed/ignore_case must be booleans when supplied, including paginated calls. Cross-pattern matches are independent (including duplicate texts); within each literal, matches are non-overlapping unless overlapping:true. Overlapping regex is unsupported.
  - Counts: count_only:true omits files/previews/hydration and scans without max_per_file; cannot combine with lines/hydrate/enclosing or pagination. JSON modes return counts and pattern_counts: occurrences sum per-pattern hits, matching_lines/files count the union, with complete/lower_bound for the selected path/glob/hidden/ignore scope. An exact max_per_file boundary is complete unless one lookahead match proves omission. Legacy count/match_count mean matching lines, not occurrences. Per-file/line pattern_counts retain identities.
  - Scope and completeness: coverage.scope is intended scope: lexical resolved_roots, environment_id/cwd, ordered include/exclude globs, hidden/ignore/symlink policies and effective limits. Resolution is not access or search proof; missing launch provenance stays null. coverage.observed reports producer file counts when available (null in legacy count mode), not an inventory of nonmatching or inaccessible paths. NUL-containing files are searched as text (coverage.scope.binary="text") so silent binary skips cannot prove absence. Unrepresentable JSON data, errors and capped line searches are incomplete lower bounds, never proof of absence; exact-capture overflow throws with evidence.delivery.truncated=true and unknown (null) scope_exhausted/result_limit_hit; recover retained output, never infer exhaustion from display truncation. Check coverage.scope_exhausted (traversal), coverage.result_limit_hit (omitted matches), coverage.read_errors (unreadable paths/rg diagnostics, not a file count), and delivery.complete/truncated separately; exhaustion alone never proves absence. delivery.preview_truncated and hydration_truncated describe content omission, independent of search_complete and hydration.complete. Keep per-file reasons and source selection/continuation metadata.
  - Hydration: hydrate:true also returns native read_file snapshots (whole-source source_sha256, deduplicated ranges, exact text and immutable recovery), with context_lines=3 (0–20); enclosing:true implies hydration and adds complete Rust/Python enclosing items when they fit. Reads at most max_hydrated_files=8 (1–32), 32 hits and 1 MiB selected payload per file; no automatic recovery/reread. matches_verified counts exact rg hit bytes verified at their UTF-8 offsets in that source snapshot, not whole-file stability since search. Unsupported structure, read failures and changed/unavailable hits remain explicit partial results; hint suggests existing paths near errors. Search completeness (`search_complete`) is independent of hydration; hydration bounds also apply during pagination.
  - Pagination: For resumable line results, set page_size=1–1000 (replaces max_per_file) and pass continuation as cursor with the same query/options, including page_size. Cursors are thread-local, opaque and source-bound; repeated cursors return the same page. Pagination retains one bounded traversal, rechecks scope membership/cwd/environment and every source's guarded SHA-256/revision before delivery, and refuses changed parameters, sources or missing/expired state with complete:false and coverage.reasons. Scope is limited to 128 files and exact command/session storage bounds; narrow path/glob on refusal. State expires after 15 minutes or session-state loss; do not splice a new search into an old traversal. pagination.start/end count matching lines in deterministic path/line order; counts are page-local, total_matching_lines covers the traversal. Guarded observations are not an atomic filesystem snapshot.
- `await await_command(r, {max_bytes?})`: pass the complete returned exec_command/write_stdin receipt as r, not a reconstruction from its handle; preserve its execution state, capabilities and any pending outcomes. Reuse a terminal receipt by its process identity/incarnation, completion_provenance and output_reference; never query its retired handle again. Exit, output drain, complete capture and delivery are independent; unresolved success remains unknown. If only an authorized live handle remains, use write_stdin with its incarnation/capabilities and pass the new receipt. A finished r returns at once. Collects into {terminal,observations,exit_code,output}, where exit_code repeats terminal.exit_code and output joins every observation's display text (neither is serialized or stored; use stdout/stderr for exact data); throws on command failure or a collection bound, preserving that object on the error's `.evidence`. Default wait/observation limits are 300 seconds/256; a collection limit is not process failure or termination. max_bytes accepts integers from 1 through 4194304 (default 4194304); positive values below 65536 are raised to 65536 so one native receipt fits. It is not a display/token budget; omit it unless needed. It counts unique observations once, not the duplicated terminal alias in JSON/storage; serialized evidence can be larger. At the bound, retain/page .evidence; resume only a live retained handle and never restart completed work.
- `await run_graph([{id,deps?,run,accept?}], {concurrency?,targets?})`: 1–256 nodes; concurrency 1–16, default 4. Returns {[id]:{status,value,input_index}}; sort by input_index for original order including numeric IDs. Without accept, explicit `success:false` rejects a result, and commands require exit_code 0 with no interaction error; arrays check every entry. Recovered unknown command outcomes do not satisfy default prerequisites. Use accept for domain-specific postconditions. On node failure, its dependents are skipped and it throws with `.results` after all started work settles.
- notify(value) queues a model-visible message without yielding. image(value,detail?) emits a data: URI, view_image result or MCP image block.
- setTimeout(callback,delayMs?) returns an ID; clearTimeout(id) cancels it. Await a callback-resolved promise to wait.
