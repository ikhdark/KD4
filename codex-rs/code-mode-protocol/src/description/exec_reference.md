# Exec cell reference

## Optional output projections

`output_projections` is a lazy Code Mode helper object, not a native tool or
permission grant. It keeps ordinary tool results and recovery available. Pass
only completed, exact owning results to the data projections.

- `await output_projections.readSymbols(path, names, {revision?, environment_id?})`: obtain the original native response for 1–64 Rust/Python symbol names. Inspect individual bindings and selector completeness.
- `await output_projections.refreshFile(path, previousBase?, environment_id?)`: returns `{observation, base}`. Store the returned base separately; print only the observation. Full, unchanged and delta observations carry source hashes; deltas use half-open Unicode code-point offsets against their named base. Partial/non-UTF-8 representations fall back to the untouched receipt.
- `await output_projections.refreshJsonFile(path, previousBase?, environment_id?)`: opt-in `refreshFile` variant for JSON data consumers that do not depend on exact layout. Pass only a base returned by this helper or `refreshFile`. After a guarded refresh, a shorter `json_layout_only` observation carries the previous and current SHA-256 when both `.json` versions parse without duplicate keys and their non-whitespace tokens match exactly. Retain the returned base for current exact text. Other cases preserve the ordinary `refreshFile` observation, including invalid, unsupported, or large input. This is a layout classification, not byte equality or a guarantee about source-sensitive consumers.
- `output_projections.groupDiagnostics(readFileResult)`: group identical complete diagnostic payloads with original one-based row numbers and optional replay attempt IDs. Original JSONL must be retained; unfamiliar or malformed records are not silently dropped.
- `output_projections.cargoEdges(metadata, packageNameOrId)`: outgoing declared dependencies and incoming path dependencies for a workspace package; keep alias, kind, target and source. Pass parsed complete stdout from successful `cargo metadata --format-version 1 --no-deps`, not a display excerpt.
- `output_projections.cargoEdgesForPackages(metadata, selectors)`: batch 1–64 lookups on the same complete metadata. Returns one edge array per selector, in input order, with the same semantics as `cargoEdges`. Use `cargoEdges` for a standalone lookup.
- `output_projections.repeatRuns(commandResult)`: collapse consecutive identical stdout lines only when the completed original is retained and stderr is empty. Runs include exact line terminators; unsuitable results stay intact.
- `output_projections.factorContracts(names)`: losslessly factor duplicate lines across a requested bundle of exact `resolve_tool` descriptions; does not alter provider schema delivery. Numeric entries index the shared table.
- `output_projections.packStructuredRows(page, fields)`: pack 1–64 explicitly named RFC 6901 fields in a complete structured selection's `value`. Repeated strings use page-local numeric indices; mixed-type columns stay literal, and null and missing fields stay distinct. Returns `{page, dictionaries?}`; use `output_projections.unpackStructuredRows(packet)` to recover the original page. Keeps plain pages when encoding would not save bytes. Native 64-bit integers remain exact; use `text(packet)` for the native JSON codec rather than ordinary `JSON.stringify`. Keep the original receipt for source identity, diagnostics and continuation; packing does not authorize or perform a read.
- `output_projections.packSparseStructuredRows(page, fields)`: same opt-in projection, additionally packs row keys as alternating field indices and values when smaller. The packet then includes `fields`; omitted indices mean absent, not null. The same unpacker handles both formats. Print with `text(packet)`, and keep the original continuation.
- `output_projections.expectedCommand(commandResult)`: for a predefined workflow that treats any stderr or nonzero exit as unexpected, return `{exit_code, artifact_id, bytes}` only for a complete, clean `quiet_on_success` result with exact retained output. Otherwise returns `null`; handle the original result and surface its diagnostics or continuation. Recover the exact transcript through the same artifact; never relaunch to obtain detail.
- `output_projections.processDelta(commandResult)`: one observation's raw/display chunks and owner identity, exit status and recovery information; does not poll or launch. On nonzero exit, error or truncation it returns the original receipt as `unprojected`. Keep the original receipt for `await_command`; print only the needed delta fields.

## Scoped context helpers

- `await read_context(path, {detail, selectors?, preview_lines?, environment_id?, previous?})`: opt-in filesystem evidence. Use `ranges` with native selectors, `preview` with a positive initial line count, `full` when the whole bounded snapshot is needed, or `defer` to acquire just a retained snapshot locator. Range/preview/full return `{query,initial,pages,selection_complete}`; keep the native receipts in script scope and print just the needed evidence. A complete `previous` for the same query can produce `unchanged:true` with no new bytes; consume the original receipt only after that confirmation. Different queries still read, even when the file bytes match. Defer returns `{artifact_id,sha256,bytes}` or fails if there is no complete retained snapshot.
- `await search_context(pattern, {owners?, consumers?, ...search_options})`: exact owner/consumer result paths get first access to native hydration slots; do not narrow the search inventory. Uses the usual search limits, receipts and cursor. When dependencies are unknown, leave both lists empty; do not infer exclusions.
- `await restore_context(locator, selectors)`: select only the required ranges from an authenticated deferred snapshot. Binds the artifact, exact canonical digest and size; returns the original native result and any verified byte-selection continuation pages, never rereads a live file or trusts a partial capture. Defer large, potentially unused material; inline small evidence if an extra model request would cost more than it saves.
- `pack_context_rows(rows, columns)`: return `{columns,rows:[...]}` for JSON row objects with exactly the listed distinct keys, in declared order. Sparse or nonuniform rows fall back to the original keyed data; keep the native receipt for source/coverage/provenance. This changes representation only, not what the selection proves.

## Engineering diagnostics

- `engineering_diff(before, after)` compares already resolved JSON values, not raw config layers. It returns typed added/removed/changed rows by JSON Pointer; object key order is ignored and array order is significant. Retain the original config/read receipts. With `{names:[...], windows?:true}` the inputs are two explicitly captured environment maps: only selected names, change labels and names absent from both are returned. Windows mode folds ASCII names and rejects ambiguous captured keys. It does not inspect or print the current process environment.
- For an explicitly declared structural JSON migration, pass JSON Patch operations under `@@ codex-json sha256:HASH` to native `apply_patch`. Bind the recipe to the current full source hash, precheck migration version and destination collisions as required, and read back. This applies the declared edits; it does not infer transformations from two schemas.
- `schema_fixture(schema, {string?: ""})` derives a deterministic JSON fixture from required fields only. It supports local acyclic object-key JSON Pointer references, const-only nodes, objects, homogeneous arrays (0–32 minimum items) and unconstrained scalar types. Scalar defaults and optional fields are not inferred; unsupported visited constraints fail. Use complete JSON schema inputs and submit the output to the real consumer before treating it as accepted.
- `await minimize_diagnostic(groups, probe, {max_runs?:64, seconds?:30})` calls an explicit sequential probe with the remaining ordered groups and milliseconds left. Return true for the same failure, false for a completed nonmatch, or null for an inconclusive observation. Keep the probe deterministic and isolated, and settle its native operations within that budget; the helper does not cancel or retry a process. The result carries probe indices and matches and distinguishes `one_minimal` (no single remaining group can be removed), `not_reproduced` and `incomplete` (which may return the last confirmed subset). It grants no tool permissions.

## Structured command workflows

- Use `tools.exec_command({program, args, env?, workdir?})` for an external executable. The same command structure works across shell dialects; select an executable appropriate to the environment. Keep runtime values in `args` or `env`, not generated shell source. `env` overlays the child's environment for that launch only. Literal argv does not prevent interpretation by the target program (including option parsing and explicit script interpreters).
- `const run = command_scope({workdir, environment_id?, env?})`: run related commands with the same explicit defaults. `await run(request, options?)` returns the native `exec_command` receipt, including any live handle. A request may override any default; an explicit `env` replaces the scope's overlay rather than merging it. No global cwd, environment mutation, or shell state persists.
- `await exec_glob({program, args?, environment_id?, ...execOptions}, {path, include_paths, exclude_paths?, exclude_directory_paths?, include_hidden?, include_ignored?, max_entries?, max_depth?, max_directories?})`: append up to 128 sorted literal file paths from one complete native listing. Patterns are case-sensitive and relative to the listing root; file paths resolve from the selected environment cwd. The helper pins the launch to the listing's environment and accepts no shell source or workdir override. No match, cutoff, or listing errors stop dispatch and retain the listing in `error.evidence`. Files may change after listing. Use a program-specific `--` delimiter when needed.
- Use an explicit shell for shell builtins, redirection or pipelines. A shell result is not a per-stage status: in Bash, immediately copy `stage_status=("${PIPESTATUS[@]}")` after the pipeline, then report the array and explicitly choose the aggregate exit policy. `pipefail` alone does not report every stage. In a PowerShell script, use `exit $LASTEXITCODE` immediately after a native child when the precise child exit code is required.
- `resolve_tool("inspect_environment")({operation:"executable", arguments:{name, all_matches:true}})` returns matching Windows PATH/PATHEXT paths in lookup order and sets `shadowed` when more than one distinct path matches. Without `all_matches`, the tool returns only the first match as before. The opt-in census does not launch files; it errors on incomplete lookup and does not identify aliases, distinct underlying images, or the executable launched by another command. Inspect the native launch receipt for launch identity where available.
- Avoid shell startup output by using direct argv or an explicit non-login shell when supported. Startup rules vary: noninteractive Bash can still source `BASH_ENV`; for a clean Bash launch use `env:{BASH_ENV:""}`. Do not discard arbitrary leading stdout lines or suppress requested profiles.
- Prefer an explicit UTF-8 setting at the producer (for example `env:{PYTHONIOENCODING:"utf-8"}` for Python). For a producer fixed to a known encoding, Code Mode `exec_command` accepts `output_encoding:"windows-1252"` or `"utf-16le"`. This decodes `stdout` and `stderr` only when the initial receipt has both complete terminal pipes within the native byte limit. Check `streams_complete`; malformed or unavailable streams have no decoded strings. The display `output`, its decoding notice, and the retained raw bytes are unchanged. Direct (non-Code-Mode) calls with this option are refused before launch. This option does not decode PTYs or carry over to `write_stdin`. Do not guess an encoding or use a combined raw transcript to reconstruct separate pipes.

## Results and failures

- Printing a whole native `exec_command` receipt with `text(result)` can show `stdout_line_runs: [[count, text], ...]` instead of the normal `output` field for large, repetitive, exactly retained stdout-only successes. Repeat each string by its count and concatenate in order; strings include their original terminator, if any. Recover the same capture with `read_tool_output` and `raw_output_artifact_id`; do not rerun the command. For an explicit exact display, emit the native `result.stdout` after checking stream completeness. Scripts, unsuccessful or incomplete commands, live/poll receipts, and output with distinct stderr do not change.

- Empty terminal drains may include `retained_output` and `retained_output_complete:true`: the complete process-owned combined UTF-8 transcript (at most 4096 bytes and within the output budget). It is not another stream delta, command-success proof or durable-artifact receipt; do not concatenate it with stdout/stderr. Larger, incomplete, binary and explicitly quiet results keep their existing recovery behavior.
- exec_command waits; one still running after the default wait returns a live `session_id` (see await_command). r.output is display text; r.exit_code is status; the host reports failed commands itself. Native stdout/stderr contain only this receipt's independent byte ranges (stream_chunks_complete); streams_complete additionally means the whole command. For polled-command parsing use await_command's top-level stdout/stderr when its streams_complete is true, not terminal's final slices. Before parsing, concatenating, or indexing a result, verify success and representation, and finish its live handle or continuations. A display string is not exact completed data. When reducing results, keep a nonzero exit with its stderr or recovery pointer. A fulfilled read can still have failed selectors: inspect selection status, completeness and diagnostics before projecting its rows.
- Native failures expose `tool_failure` (also on caught exceptions): inspect `code`, `execution_state`, `effects`, `retry_safe`, `field_errors`, `safe_next_actions` and `live_operations` together. Execution is `not_started` only for owner-confirmed pre-execution rejection, `completed` for an actual invocation receipt (not child-process exit or successful effects), otherwise `unknown`, including missing/lost responses and legacy states. Unknown never proves failure or retry safety. `field_errors` uses exact RFC 6901 argument paths (empty means root), public expected constraints and corrections, never rejected values; omitted diagnostics are marked in details. A `read_file` rejection of the snapshot-only `tail` selector gives a live-file correction; the caught failure retains the original branch diagnostics in `details.selector_branches` for explicit inspection. PowerShell syntax refusals may omit repeated reason text from the display; caught errors still retain the native failure. Codes distinguish invalid syntax, stale input, missing/ambiguous anchors, permission denial, retryable failure, timeout, cancellation and uncertain effects; none grants permission to retry. Resume an existing operation using its owner-issued handle rather than launching a duplicate; cancellation is not rollback. Legacy/unclassified diagnostics remain non-retry-safe.
- Nested deadlines: { timeout_ms } overrides the host default. Expiry reports `tool_failure.code="timed_out"`, not cancellation or process exit; the process may still run. Inspect late evidence on `error.results.completed.value` and any live handle before considering a retry.
- `operation_history` (on results or `tool_failure.details`) retains attempt provenance and surfaces earlier outcomes for the same exact input. Its typed-context fingerprint is not proof of a shared cause; external state may be unknown. Memory is advisory, not a retry ban or permission: changed conditions or transient failures can justify retry after checking effects/live handles. Retry-owner budget receipts distinguish reserved retries, entered attempts, transport scope and agent attempts; unlimited and unknown values are explicit.

## Deterministic recipes

- `await apply_literal_edits(from, to, files)`: apply one exact literal substitution to 1–64 explicit files in one native patch. Pass current `{path,source_sha256,count?}` selections with full source hashes. Count defaults to 1; 0 asserts absence. There is no regex, globbing or normalization.
- `await apply_patch_plan({update, add, guard})`: assemble one native patch from up to 64 total rows. Use `update:[[path,source_sha256,start,end,lines]]` for inclusive one-based range replacements, `add:[[path,lines]]` for create-only files, and `guard:[[path,source_sha256]]` for read-only dependencies. Group adjacent rows with the same path and source hash to edit multiple ranges of one snapshot; rows with a new hash retain their ordered verification boundary. Hashes are full and lines are strings without terminators. Omit unused arrays. Use `apply_patch` directly for other forms.
- Both helpers validate input shape before dispatch, then return the original native receipt. Native guards, permissions, endpoint conflicts and recovery still apply. Preflight does not make per-file publication atomic; inspect `changes_exact` and reconcile before retrying.

- `await ensure_json_value({path, pointer, value})`: for a declared update to an existing JSON scalar, use an RFC 6901 pointer (empty selects the root). Types must match; numbers must be safe integers. A complete equal value returns `{status:"unchanged",value,source_sha256}` without dispatching a patch. Otherwise it submits one source-hash-guarded native JSON replace, checks its receipt, and reads back before returning `status:"verified"`. Missing or ambiguous values are not created, and neither a stale hash nor unverified readback is retried. An unchanged result describes the observed source, not a lock against later edits.
- `await emit_file_report({path, pointer="", fields:[{name,pointer}], format="json"})`: render 1–64 declared fields from one native JSON file snapshot. Field pointers are relative to the base pointer. Incomplete, missing or ambiguous selections emit no report. Uses the same formats, limits and escaping as `extract_result`; emits only the rendered text and returns its provenance. Put it in a `deliver:true` cell only when it is the complete requested answer. Without that opt-in, the text is ordinary tool output; existing delivery and completion gates still apply.

Compose only when the requested transform and next action are already known. Do not guess a repair, infer permission, parse a display as exact data, or declare arbitrary tool success to be task completion. The existing delivery, plan, schema, pending-input and recovery gates still apply. Do not read this reference just to rediscover an eager contract.

- A declared extraction can read a native structured result, check its completeness, call `extract_result` with known pointers, and deliver its text in the same cell. Preserve the returned provenance; extraction is not source-completeness proof.
- A declared edit can construct a hash-bound patch from that cell's source receipt rather than regenerating old lines. For example, only for a request to set `settings.json`'s existing boolean `/enabled` to true:

```js
// @exec: {"deliver": true}
const source = await tools.read_file({path:"settings.json", selectors:[{kind:"json_pointer",pointer:"/enabled"}]});
const row = source.results?.[0];
if (source.complete !== true || source.results?.length !== 1 || row?.status !== "ok" ||
    row.complete !== true || typeof row.value !== "boolean" || typeof source.source_sha256 !== "string")
  throw new Error("complete current boolean selection required");
// A complete current observation already satisfies an idempotent request.
if (!row.value) {
  const operations = [{op:"replace",path:"/enabled",value:true}];
  const patch = "*** Begin Patch\n*** Update File: settings.json\n@@ codex-json sha256:" +
    source.source_sha256 + "\n+" + JSON.stringify(operations) + "\n*** End Patch";
  const changed = await tools.apply_patch(patch);
  if (changed.success !== true || changed.changes_exact !== true)
    throw new Error("edit rejected or effects uncertain; retain its receipt before repair");
}
text("settings.json /enabled is true.");
```

- If requested verification/readback is mechanical, await it after the successful operation and before delivery; do not stop merely to have the model announce the next known call. A failed prerequisite stops dependent work, not independent receipt recovery.
- For whole required files use `read_files(paths,{full:true})`, check every row's status and `file_complete`, and consume only that original snapshot. For known ranges batch selectors. For retained output invoke the producer's `recovery.arguments` with `read_tool_output` in the same cell, narrowing to the required records; follow only required, resumable `remaining_selectors`. Do not reacquire the source or relaunch a producer to recover its output.
- Start authorized independent reads/root work before awaiting a long-lived dependency. Use `Promise.allSettled` for independent fallible operations and `run_graph` for declared dependency/postcondition edges; keep shared writers and builds exclusive. Once dependent work is all that remains, use its existing command/worker wait owner rather than model-mediated polling.

## Stored values

- JS bindings reset per exec; store(key,value)/load(key) retain JSON-serializable data, native results included (exact integers survive; functions and other non-JSON values do not). Store a compact projection when the quota matters. Native integers are JS numbers unless they exceed 2^53, where they become BigInt and JSON.stringify throws; prefer text(result) to print a whole result. Load large JSON once per computation and compare stable keys, not object references across loads. Keep one working body, retiring obsolete copies before storing replacements. Summarize already-consumed machine data without reprinting it. deleteStored(key) drops duplicates. Failed quota cells discard staged stores; check listKeys before resuming. listKeys({after?,limit?}) returns a page object, not an array: inspect its .keys array, then use .next_after to continue (1-64 keys, default 32). First-line // @exec: {"persist":true} preserves completed values across host restart.

## Command display normalization

When a completed native `exec_command` result has a complete retained output artifact, its printed `output` may remove complete numeric ANSI SGR sequences, including semicolon and colon forms. `output_display_normalized: "ansi_sgr_only"` identifies this presentation-only change; the original stdout/stderr and exact retained command log remain unchanged. The printed result retains `raw_output_artifact_id`, `raw_output_artifact_bytes`, and `output_reference` so consumers can recover literal bytes. Unrecognized controls, incomplete sequences, live commands, `write_stdin` polls and incomplete retention stay unchanged.

A finished `write_stdin` poll can have an empty final chunk after stdio was drained. Use its printed `recovery` to retrieve the whole transcript; only an exact whole transcript already in the displayed `output` can make that recipe redundant.

## Binary snapshots

A default regular-file read classified as likely binary may return a complete, immutable binary snapshot for a file up to 64 KiB. It reports `artifact_id`, `source_sha256`, `canonical_bytes` and `retained_artifact_complete: true` without displaying encoded bytes. Use `read_tool_output` with that ID and a byte-range selector; the text selection still did not succeed. Explicit encoded `read_file` ranges remain live revision-bound reads; when no snapshot is available, the default response keeps its live binary recovery recipes.

## Helpers

- `await select_output({artifact_id, selectors, source_thread_id?, max_bytes?}, {expected_sha256?, expected_bytes?, max_calls?, max_bytes?, preserve_line_windows?}?)`: select retained output and automatically finish eligible recovery before returning `{initial,pages,selection_complete}`. Use it when the task is ready to consume an explicit selection in the same cell. Omit `source_thread_id` for this thread; use the verified descendant's ID for a descendant. Optional expected hash and size refer to the canonical retained artifact, not to the selected spans. For a command log, take the artifact ID from the original producer's receipt and pass its retained byte count when available.
  - For 1–64 known line windows of one authenticated snapshot, set `preserve_line_windows:true` and pass both expected canonical hash and byte length. One native read returns the original receipt plus `line_windows:[{start,end,text}]` in caller order, including duplicates. Incomplete windows refuse with native evidence, not a byte replay or a file reopening. Print only the windows needed downstream.
  - A complete selection from a complete capture returns directly, including command logs whose native authenticity is `unverified`; the helper does not upgrade that label. The first `max_bytes` limits the native initial read. The second object's limits apply to `recover_output` only, which is called for authenticated `budget`/`page_limit` byte continuations. Unsupported continuations, capture gaps or mismatched identity stop without a follow-up read and retain the initial receipt in `.evidence`. Native dispatch errors propagate. Keep raw `read_tool_output` for metadata, incomplete command logs and callers that need to checkpoint before deciding whether to continue.
- `await recover_output(initial, {max_calls?, max_bytes?})`: explicitly continue one original native `read_tool_output` snapshot receipt for nonempty byte selections. Pass the complete receipt, not a printed projection, command log, `read_file` envelope or reconstructed recipe. Returns `{initial,pages,selection_complete}`; pages contain exact native results, not concatenated text. Completion concerns only those original selections, not the whole artifact or task. A complete initial receipt dispatches nothing. On failure, `.evidence` retains the initial packet, every received page and any native cause; a helper limit additionally retains the last verified `recovery` recipe. No retry, producer replay, file reopening, checkpoint publication or permission grant occurs.
  - Call this after the initial read/store cell has successfully completed when that acquisition must survive interruption. This helper uses the existing cell transaction: cancellation does not commit new named-state writes or erase the earlier checkpoint. Catch ordinary errors to retain/inspect `.evidence`; resume interrupted work through the original owner, never infer rollback or successful completion.
  - Only authenticated complete retained snapshots with fixed artifact/hash/size/source-thread identity are eligible. It follows exact advancing `budget`/`page_limit` byte remainders through normal native dispatch. Cancelled/still-writing stops, drift, unavailable bytes, terminal/invalid selectors, overlap and non-progress stop with evidence. `resumable:true` alone is not sufficient. Other selector families remain available through the native tool, not this helper.
  - `max_calls` is 1–64 (default 64); `max_bytes` is 1–8388608 (default 8388608), the aggregate serialized packet budget including `initial`. One maximum 1 MiB native packet is reserved before each dispatch; a tighter remaining budget can stop before a smaller page that might fit. Native source/page/serialized limits remain unchanged. The failing native packet is retained even if it exceeds the helper bound; no further call is launched. Limits are not display budgets.

Prefer these over equivalent read/search/poll plumbing; preserve scope, budgets and failure evidence.
`search_files` uses the registered read-only `file_search` backend (also `inspect_files(search)`) in local full-disk-read environments. It constructs fixed ripgrep arguments, not a shell command, and owns bounded capture/cancellation; worker shell permissions do not change. Older or unsupported hosts retain the command-backed helper and its existing execution-permission requirement. Native `read_file` search selectors remain available for known files without command execution.
- `extract_result(result, {fields:[{name,pointer}], format:"json"|"text"|"csv"|"tsv", row?:{pointer,where:[{pointer,value}]}})` returns `{text,values,provenance}` from an unmodified native structured tool result (also after store/load when trusted metadata fits the existing quota). Declare 1–64 uniquely named fields with exact RFC 6901 pointers; optional row selects exactly one array member by typed equality predicates (1–64). Missing fields/rows, multiple matching rows, invalid declarations, clones and edited results throw; no text parsing or guessed fields. JSON preserves null and exact integers; text requires one non-null scalar; CSV/TSV require non-null scalars, preserve field order and quote delimiters/quotes/newlines. Declarations and the complete return are capped at 1 MiB. Provenance retains native tool/call identity, available source metadata, the declaration and resolved pointers, not proof of source completeness. Use `text(extract_result(r, declaration).text)` with `deliver:true` to deliver the declared answer without another model round; existing success, output-schema and delivery gates still apply.
- `await read_files(paths, {full?, concurrency?, revision?, source_hashes?, refresh_hashes?, environment_id?})`: 1–32 paths; Promise.allSettled rows: {path,status:"fulfilled",value} or {path,status:"rejected",reason}, never outer "ok". value={initial,pages,file_complete,consistency}; text is in initial.results/pages[].results. revision is a full immutable commit OID; native reads verify commit and batch repository/environment identity. Otherwise source_hashes declares every exact path's source_sha256, whole or its first 12 characters; mismatches reject per file with evidence. Undeclared consistency is unknown, readable as value.consistency but left out of a printed row. full defaults false; true recovers only the original retained snapshot. Matching per-file identities, opens and hashes are not an atomic live-workspace snapshot. Check status, consistency and file_complete; byte coverage is not semantic review.
  - For repeated live reads, pass `refresh_hashes` instead of `revision` or `source_hashes`. Supply the full prior `initial.source_sha256` for each path whose complete content you retained. `value.unchanged:true` has `file_complete:false`, no new content and no new recovery locator; reuse the prior only after matching its path, environment, representation and hash. Without that complete prior, reacquire the required bytes. Changed and unlisted paths use the ordinary read/recovery contract; errors are not unchanged receipts. This does not establish that dependent runtime behavior is unchanged.
- `await search_files(pattern, {page_size?, cursor?, count_only?, overlapping?, path?, glob?, lines?, max_per_file?, ignore_case?, fixed?, hidden?, no_ignore?, hydrate?, enclosing?, context_lines?, max_hydrated_files?, preferred_paths?})`: ripgrep returning {files:[{path,count,lines?,source?,hydration?}],match_count,complete,errors?,hint?}. lines adds {line,text}, default max_per_file=10. In printed complete results, dense ordered hits may carry `file.line_ranges` (ascending inclusive `[start,end]` pairs); expand them in order to recover the omitted `line` of each corresponding `file.lines` entry. For plain dense hits with uniform counts, `file.line_texts` replaces those rows: align the strings with the same ranges and use `file.line_pattern_counts` for every hit. Scripts still receive the original `file.lines` and should use it directly. Prefer up to 32 exact result paths, in order, for the existing hydration budget when owners or consumers are already known. Unmatched paths do not use hydration slots. Preferences do not filter or reorder the search inventory; pass the same preferences when continuing a search.
  - Matching: A string defaults to ripgrep regex semantics; fixed:true passes the supplied single-line text unchanged via argv, without regex interpretation or shell interpolation. Invalid regex is an error, never a literal fallback. Patterns reject NUL/lone surrogates and fixed strings reject LF rather than silently splitting into alternatives. An array of 1–64 strings or {id,pattern} entries shares one tree scan; arrays default to fixed:true and reject fixed:false. Strings get zero-based string ids; explicit ids must be unique. Multi-pattern literals are 1–1024 UTF-8 bytes each, without newlines/lone surrogates. Default case-sensitive; ignore_case folds ASCII only for arrays/overlapping literals, otherwise ripgrep Unicode rules apply. Every result reports semantics.fixed, case_sensitive and case_folding (none, ascii or ripgrep_unicode), including misses, errors and cursor refusals. fixed/ignore_case must be booleans when supplied, including paginated calls. Cross-pattern matches are independent (including duplicate texts); within each literal, matches are non-overlapping unless overlapping:true. Overlapping regex is unsupported.
  - Counts: count_only:true omits files/previews/hydration and scans without max_per_file; cannot combine with lines/hydrate/enclosing or pagination. JSON modes return counts and pattern_counts: occurrences sum per-pattern hits, matching_lines/files count the union, with complete/lower_bound for the selected path/glob/hidden/ignore scope. An exact max_per_file boundary is complete unless one lookahead match proves omission. Legacy count/match_count mean matching lines, not occurrences. Per-file/line pattern_counts retain identities.
  - Scope and completeness: coverage.scope is intended scope: lexical resolved_roots, environment_id/cwd, ordered include/exclude globs, hidden/ignore/symlink policies and effective limits. Resolution is not access or search proof; missing launch provenance stays null. coverage.observed reports producer file counts when available (null in legacy count mode), not an inventory of nonmatching or inaccessible paths. NUL-containing files are searched as text (coverage.scope.binary="text") so silent binary skips cannot prove absence. Unrepresentable JSON data, errors and capped line searches are incomplete lower bounds, never proof of absence; exact-capture overflow throws with evidence.delivery.truncated=true and unknown (null) scope_exhausted/result_limit_hit; recover retained output, never infer exhaustion from display truncation.   - Hydration: hydrate:true also returns native read_file snapshots (whole-source source_sha256, deduplicated ranges, exact text and immutable recovery), with context_lines=3 (0–20); enclosing:true implies hydration and adds complete Rust/Python enclosing items when they fit. - `await retrieve_source({exact, related?, relax?}, {path?, glob?, hidden?, no_ignore?, max_per_file?, force_fresh?})`: opt-in source retrieval for up to 32 exact and 32 related literal strings. Matching is case-sensitive and uses the same native `search_files` scope and line limits. Tagged exact matches are reported separately as `{path,line,literal,occurrences}` even when a line preview clips the literal. Use a native source read when the full line matters.
  - `combined` is the original shared search receipt. If an incomplete shared search could hide exact matches behind related matches, `exact_fallback` is a separate exact-only receipt. `exact_complete` applies to `exact_matches`; `related_matches` may be partial when `combined.search_complete` is false. Preview and search completeness remain separate. A replay does not create an atomic snapshot.
  - `relax:true` takes one exact phrase and no related terms. For a plain phrase of 2–8 ASCII identifiers (each at least three characters), the same scan looks for the constituent literals. `selection` is `exact`, `relaxed`, `none`, or `incomplete`; related matches are selected only after a complete exact miss. A failed scope is not a miss, and punctuation is not rewritten. Prefer ordinary `search_files` for known exact hits, regex, pagination or hydration.
- `await await_command(r, {max_bytes?})`: pass the complete returned exec_command/write_stdin receipt as r, not a reconstruction from its handle; preserve its execution state, capabilities and any pending outcomes. Reuse a terminal receipt by its process identity/incarnation, completion_provenance and output_reference; never query its retired handle again. Exit, output drain, complete capture and delivery are independent; unresolved success remains unknown. If only an authorized live handle remains, use write_stdin with its incarnation/capabilities and pass the new receipt. A finished r returns at once. Collects into {terminal,observations,exit_code,output}, where exit_code repeats terminal.exit_code and output joins every observation's display text (neither is serialized or stored; use stdout/stderr for exact data); throws on command failure or a collection bound, preserving that object on the error's `.evidence`. Default wait/observation limits are 300 seconds/256; a collection limit is not process failure or termination. max_bytes accepts integers from 1 through 4194304 (default 4194304); positive values below 65536 are raised to 65536 so one native receipt fits. It is not a display/token budget; omit it unless needed. It counts unique observations once, not the duplicated terminal alias in JSON/storage; serialized evidence can be larger. At the bound, retain/page .evidence; resume only a live retained handle and never restart completed work.
- `await run_graph([{id,deps?,run,accept?}], {concurrency?,targets?})`: 1–256 nodes; concurrency 1–16, default 4. Returns {[id]:{status,value,input_index}}; sort by input_index for original order including numeric IDs. Without accept, explicit `success:false` rejects a result, and commands require exit_code 0 with no interaction error or outstanding collection handle; arrays check every entry. Status-only observations and recovered unknown command outcomes do not satisfy default prerequisites. Use await_command for collection or accept for a domain-specific postcondition, such as observing exit without collecting output. On node failure, its dependents are skipped and it throws with `.results` after all started work settles. Before admitting a dependent, the scheduler checks that all its prerequisites fulfilled. A skipped row's `blocked_by` lists its nonfulfilled prerequisites in declared dependency order.
- Missing or self dependencies and dependency cycles throw a `TypeError` before any callback starts, even outside `targets`. Catch it in the cell and inspect `error.graph_conflict`: `{kind:"missing_dependency"|"self_dependency",node_id,dependency_id}` names the first invalid edge; `{kind:"dependency_cycle",cycle}` lists one directed cycle in dependency order, repeating its first node at the end. This evidence neither chooses an edge to remove nor authorizes automatic retry. Other graph errors do not gain this field.

Decision IDs must be distinct and terminal: neither a local step nor another decision can depend on one. Split dependent choices across cells. Return the `decisions` array as ordinary tool output when a choice is needed, never as `deliver:true` output. The helper does not invoke the model, print, authorize actions, update requirements, or persist/retry work. `settled` describes this graph only, not permission to finalize the turn.
- `await spawn_read_wave([{id,message,producer?}])` (1–256 rows): default for authorized ordinary read-only batches. Rows with the same explicit producer (native task name) still alias only if their messages match exactly; named and unnamed groups never merge. Each ID is preserved.
