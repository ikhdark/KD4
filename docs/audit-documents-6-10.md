All five files were read in full. Their recommendations were treated as claims to investigate, not instructions to execute. This audit uses the current local checkout, including compatible changes from the user's other concurrent audit tasks. No upstream synchronization, publication, binary replacement, or Desktop restart was performed.

## Claim dispositions

Source paths refer to files under `codex-rs`; shortened core paths are relative to `core/src`.

| Document / claim | Verification and action |
|---|---|
| 6.1 Originating attempt required for receipt sealing | Confirmed. Production sealing now requires an attempt ID. A turn captures its binding at entry; terminal callbacks and completion watchers use that identity and reject a renewed attempt. The unversioned convenience method is test-only. See `core/src/agent/task_coordinator.rs`, `session/turn.rs`, `session/mod.rs`, and `agent/control.rs`. |
| 6.2 Typed completion drops surfaced result | Confirmed. Receipt projection retains `CompletedWithSurface` for the same attempt after checking pending gates. Stale attempts cannot contribute a surface. See `agent/status.rs`. |
| 6.3 Missing receipt loses recorded evidence | Confirmed. Fallback reloads the attempt after evidence finalization, links its terminal validation calls, identifies the execution outcome and attempt, and explains that criterion acceptance remains unverified. Finalization errors remain visible as risks. It does not invent passing evidence. |
| 6.4 Overridden prompt file still read | Confirmed and fixed by the overlapping config audit. Explicit prompt overrides bypass lower-priority file reads. See `core/src/config/mod.rs`. |
| 6.5 Default multi-agent instructions duplicate broad requirements | Confirmed and consolidated by the overlapping config audit. Shared rules occur once; root guidance scopes work to affected contracts and dependencies. No performance improvement is claimed without measurement. |
| 7.1 Queued child result misses first parent request | Confirmed. The overlapping queue/control audit added a mailbox-only initial drain and wired it into the parent turn while retaining user queue ordering and cancellation ownership. See `session/input_queue.rs`, `session/turn.rs`, and `agent/control_tests.rs`. |
| 7.2 Replace history inheritance with evidence handoff | The described message filtering exists, but a task capsule and typed evidence/receipt interfaces already exist. Replacing FullHistory/LastN with another protocol is a design proposal; the documents do not establish that the current handoff fails an acceptance requirement. No second handoff system added. |
| 7.3 Separate admission/execution and add runtime leases | Reservations deliberately cover preparation and submission; cold loads already share ownership and residency accounting. A new scheduler and lease model would change concurrency semantics. No reproduced incorrect execution or permit release required that redesign. |
| 7.4 Cold agents invisible; compact status | Confirmed for runtime-only `get_status` and the `agents` listing, although `typed_tasks` already exposes durable bindings. Missing runtimes now fall back to the exact registered thread/attempt's durable terminal receipt; listing includes every registered identity, uses that path when a receipt exists, and reports `runtime_loaded` without loading the actor. Changing full result-bearing status payloads to a new compact API remains a separate design proposal. |
| 7.5 Serial cleanup and no-progress eviction retry | Confirmed and repaired by the overlapping lifecycle audit using runtime-owned cleanup and bounded eviction progress. See `agent/control/spawn.rs`, `agent/control/residency.rs`, and their tests. |
| 8.1 Snapshot is not proof of retained content | Confirmed. AGENTS checks its latest substantive body, scope, and removal; app/plugin checks the latest availability or revocation. Environment snapshots record the digest of the exact admitted fragment, so an older cwd match cannot conceal a lost shell, status, removal, or cleared field. Legacy snapshots conservatively replay once. |
| 8.2 First-come budget can omit mandatory state | Confirmed. Required sections are admitted before optional sections. Whole required content uses the existing request-level context limit; optional catalogs yield. Optional subagent details are separately bounded. |
| 8.3 AGENTS middle truncation loses authoritative rules | Confirmed. Removed partial instruction delivery. Required bodies remain complete, including middle rules, or request-level overflow handling stops the request. Old partial snapshots replay the complete body. |
| 8.4 Readiness and clearing environment values | Confirmed and repaired with the compatible environment changes. Starting-to-available is explicit and removed shell/OS values clear explicitly. Every emitted update after a prior context declares authoritative replacement, so losing an intermediate clearing message cannot resurrect an omitted field. See `context/world_state/environment.rs`. |
| 8.5 Freshness change repeats entire AGENTS body | Confirmed. A freshness-only change emits a short observation when the retained scoped body is intact. Body changes still emit replacements. The stable projection must retain the substantive body alongside this observation. |
| 9.1 Repeated occurrences share provenance on replay | Confirmed. Reprojection now matches source occurrences in order and carries their aligned sidecars. Ambiguous changed duplicate counts fall back conservatively instead of assigning another occurrence's category/current-input flag. |
| 9.2 Current input inferred from text/metadata | Confirmed collision cases repaired: internal injected user context does not become task input, ordinary user text matching a stable manifest remains user input, and replay preserves occurrence flags after provider IDs disappear. A wholesale new persistent message-identity protocol was not needed for those cases. |
| 9.3 Global exact-text categorization | Confirmed. The compatibility matcher assigns only unique developer occurrences; user quotations and duplicate matches do not acquire injected categories. Existing occurrence-specific assignment remains available. Ordinary user boundaries bypass stable-text categorization. |
| 9.4 Empty manifest still hashes history text | Confirmed. Empty-category lookup skips text hashing; normal aligned measurement does not recompute replay fingerprints. |
| 9.5 Internal context can close its own envelope | Confirmed. Rendering escapes its own delimiter prefixes while preserving other source text. Recognition rejects raw nested or early closing delimiters, including legacy goal envelopes. |
| 10.1 Single-slot cache; shared refresh results | Confirmed account-thrashing defect: replaced the slot with a bounded 16-scope cache and tested alternating identities. Per-identity refresh locks remain. Forced calls explicitly request fresh data; failed calls remain retryable. Sharing errors or coalescing every forced call would change those contracts and was not established as necessary. |
| 10.2 Best-effort disk persistence delays return | The caller does await the blocking publication worker, as described. The worker also retains refresh ownership through atomic persistence. Removing that wait requires a new ordered background writer; no reproduced correctness defect or measured latency justified it in this audit. |
| 10.3 Invalid app policy becomes permissive | Confirmed. Policy parsing now returns an error. Exposure withholds app tools, dispatch blocks with a visible tool result, connector enablement becomes false, and installed-app projection propagates the policy error. Native MCP tools retain their independent path. |
| 10.4 Inconsistent connector ID trimming | Confirmed. A shared canonical ID helper trims whitespace, rejects blanks, and preserves case across discovery, projection, policy lookup, and suggestion joins. Noncanonical policy keys are rejected rather than silently bypassed. |
| 10.5 Disk metadata loses TTL freshness | Confirmed behavior, but it is an explicit existing revalidation policy: disk entries provide metadata immediately while only process-fetched entries are fresh for live listing. The regression suite explicitly requires a refresh after process-cache reset. Persisting TTL across restart is a policy change, not a demonstrated failure. |

The secondary prediction about `BudgetLimited` waiting forever is not established in this checkout: the enum is mapped to an interrupted status, but no current core producer emits that abort reason; generation exhaustion has an explicit status-affecting error path. No speculative terminal-state change was made.
